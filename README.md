# 拾光阅读器

从 [sudugu.cc](http://sudugu.cc) 起家做出来的一个干净的桌面阅读器：无广告、无弹窗、自带书架和阅读进度，
只用 Python 标准库实现，**不需要安装任何第三方依赖**。

内置八个书源：**速读谷**（网页站）、**七猫**（正版书库，走 App 接口）、**书旗**（正版书库，走 App 加密接口）、
**全本小说网**（网页站，qbxs.net）、**八叉书库**（网页站 + 正文签名接口，bcshuku.com，成人向内容站点）、
**八一中文网**（网页站，81shuku.info）、**得奇小说网**（网页站 + 异步正文接口，deqixss.com）、
**爱丽丝书屋**（网页站，alicesw.com，成人向内容站点，**需要代理**，见下文）。
搜索时十个源一起出结果，书架上不同来源的书可以混着放，阅读器对它们完全一致。

除了小说，也能看漫画：**漫客栈**、**包子漫画**、**快看漫画**、**大人漫画**（在线漫画源）和**本地漫画包**（CBZ / ZIP / 图片版 EPUB）。
书架、目录、进度、阅读设置都和小说共用一套，卡片上多一个「漫画」小标、单位从「章」变成「话」。

## 怎么用

1. 双击 **`拾光阅读器.vbs`**（无黑框，直接弹出应用窗口）。
   想把快捷方式放到桌面：右键 `拾光阅读器.vbs` → 发送到 → 桌面快捷方式即可。
2. 第一次打开是空书架，点「发现」或右上角放大镜找书 → 进书页 → 「加入书架」。手机端为底部悬浮标签栏（书架 / 发现 / 我的）。
3. 阅读中按 `←` / `→` 翻章（漫画是翻页），`T` 打开目录，**点一下正文隐藏/呼出底部工具栏**（沉浸阅读），`Esc` 返回。
   看漫画：直接搜（包子、快看支持关键词），或者书架三点菜单「添加在线漫画」粘作品链接，再或者「我的」→ 导入本地 `cbz/zip` 漫画包。

> 调试时用 `拾光阅读器-调试.bat`，能看见控制台日志和报错。

| 书签 | 阅读器右上「更多」→「加入书签 / 移出书签」，按章记录；「我的」→ 书签与笔记里可跳回并删除 |
| 划线 / 笔记 | 长按正文段落（桌面双击）弹出面板：可只划线，也可写笔记；划线以暖色底纹标记、重进本章仍在；点已划线段落可看笔记或删除 |
| 备份 | 「我的」→ 备份：导出书架、阅读进度、书签笔记、设置、历史与统计（iOS 走系统分享，桌面直接存文件）；恢复时按「更新时间较新优先」合并，不覆盖你现有的书 |
| 阅读统计 | 「我的」顶部：今日时长、连续阅读天数、累计时长与章数，附最近 14 天柱状图；只要在读书就会自动累计 |
| 阅读历史 | 「我的」→「继续阅读」：最近读过的书按时间排列（没加入书架的也在），显示读到的章节与时间，点一下接着读，可单条移除或清空 |
| 换源 | 书页或阅读器三点 →「更换书源」：用书名 + 作者在其余书源里找同一本书，选中后按章节名对齐目录、迁移阅读进度与书架记录，并记住这次选的源 |
| 书源健康 | 「我的」页顶部：8 源并发探活（可用状态、响应耗时、失败原因）、爱丽丝当前代理端口、每个源的启用开关（关闭后不参与搜索与换源），可手动「重新检测」 |

## 工作原理

- 本地起一个只监听 `127.0.0.1:8791` 的 HTTP 服务，前端是普通网页。
- 用 Edge 的 `--app` 模式打开，所以窗口没有地址栏、标签页，看起来就是一个原生应用。
- 页面每 20 秒发一次心跳，窗口关掉 3 分钟后服务自动退出，不留后台进程。
- 解析要点：这一站是杰奇 CMS，正文在 `<div class="con">`，目录在 `#list`，目录超过 1000 章会分页（`/书号/2`），
  章节正文可能分成 `_2.html`、`_3.html` 多页，程序会自动串起来；个别最新章节链接是 `data-enc` 的 Base64，也已处理。
- 多书源：书籍 id 形如 `qm:143170`（七猫）、`sq:34078`（书旗）、`qb:1389`（全本）、`bc:58363`（八叉）、
  `bl:2022`（八一）、`dq:165`（得奇）、`ali:49271`（爱丽丝）、`mkz:217087`（漫客栈漫画）、
  `gs:<作品slug>`（包子漫画，slug 就是 `/manga/<slug>` 的最后一段）、
  `kk:1165`（快看漫画，纯数字作品 id），
  或纯数字 `4389`（速读谷），本地导入的是 `loc:<hash>`；
  章节地址形如 `qm://143170/36898237`、`sq://34078/2180322`、`qb://1389/2443879.html`、
  `bc://58363/chapter68.html`、`bl://2022/1438450.html`、`dq://165/138027.html`、
  `ali://book/50585/be101e8b60c8d.html`、`mkz://217087/74017825`、
  `gs://douluodalu5-zhongji/927496`、`kk://1165/43727`。
  `core.book()` / `core.chapter()` 按前缀分派，前端的路由、书架、进度都不用区分来源。
  漫画和小说在数据上只差一个 `kind: "comic"`（章节对象从 `paras` 正文换成 `pages` 图片列表），
  前端的 `isComic()` 一处判断就切换整套渲染与手势。
- 七猫正文是 AES-128-CBC 加密的：Base64 解码后前 16 字节当 IV，其余用固定 key 解密。
  环境里没有加密库，`reader/aes.py` 是手写的纯标准库实现（已用 FIPS-197 标准向量验证）。
- 七猫榜单走的是网页版接口 `www.qimao.com/api/rank/book-list`（`is_girl / rank_type / date_type / page`），
  不需要 App 签名；返回的书籍 id 与 App 接口一致，所以榜上的书点进去能直接看目录和正文。
- 书旗是 App 加密接口：请求体 JSON 用 2048 字节 keystream 做 XOR 再 base64，签名是按键名排序的 MD5，
  头部还要带同样的加密串（`reader/shuqi.py` 完整复现）。H5 站点必须用 `okhttp/3.12.13` 的 UA，
  浏览器 UA 会拿到 403 拦截页；目录取 H5 `/chapter?bid=`（约 1.2MB），正文走 CDN 的明文 JSONP。
- 榜单的坑：站点的 `/top/lastupdate/N.html` 是个兜底页，内容与 `/top.html` 完全一样（都只有 20 本，且不分页），
  所以「最新更新」改取首页的真实更新顺序；「阅读排行」固定一页；只有「完结小说」（`/quanben/N.html`）是真分页。
- 榜单与分类结果会本地缓存（榜单 10 分钟、分类 5 分钟）。抓取失败或抓到空列表时返回上一份缓存并提示，
  不会把页面刷成空白。

## 注意

- 所有文字内容来自第三方站点，本程序只做本地渲染与缓存，请自行确认使用范围，支持正版。
- 全本小说网是传统 HTML 站点：搜索/排行都是 `table#rankinglist`，详情页一次给出全量目录（两千多章约 230KB），
  长章节在正文页被拆成 `_2.html`、`_3.html`，抓取时顺着 `#next_url` 拼完；每页首尾各有一条站点水印，
  用「含 qbxs / 一秒记住」和「不含汉字」两条规则过滤。站点对非浏览器 UA 返回 403，请求头必须是桌面 Chrome UA。
  封面：只有详情页与分类卡片带 `<img>`，搜索/榜单的表格里没有图，按站点固定路径
  `/images/{bid//1000}/{bid}/{bid}s.jpg` 推导（59 本实测 58 本命中，个别书站点自己没传图会返回默认占位图）。
- 八叉书库是传统模板站，但正文另走接口：章节页里内嵌 `url/mobile/isk/novel/chapter/t/n/sign`
  八个参数，表单 POST 到 `/conapi.php` 才返回 JSON 正文，参数直接照抄页面即可（会过期，所以每次现取）。
  两个坑：① 搜索必须先请求 `/e/search/index.php?...&searchget=1` 拿 302 里的 `searchid` 才能看结果；
  ② 目录里混了隐藏的 SEO 干扰项（`aria-hidden` / `overflow:hidden` / `rel="nofollow"`），
  会把别的书的章节塞进来，必须过滤并按书号校验。
- 八叉书库为成人向内容站点，`bcshuku.com / img.8xsk.top` 常被网络代理或运营商屏蔽；
  被拦时页面会提示「代理返回 502」而不是白屏，已抓过的榜单/目录仍可从缓存读取。
- 七猫与书旗使用的是各自的 App 私有接口（算法来自用户提供的「阅读」书源），
  仅供个人本地阅读使用，不要用于分发或二次发布；接口随时可能变动或失效。
- 八一中文网是标准杰奇 CMS：搜索走 `POST /modules/article/search.php`，分类 `/拼音_1_{page}.html`（7 类 × 50 页 × 30 本），
  详情页一次给全量目录（两千多章约 250KB），正文单页干净无分页。两个坑：① 原域名 `blxs.la` 已 301 到 `81shuku.info`；
  ② 站点对不带 `Accept-Encoding` / `Referer` 的请求会回一张 442 字节的自动跳转脚本（跳广告站），看着像域名被劫持，
  其实声明 gzip 并解压就正常。它连封面图都带 `Content-Encoding: gzip`，所以 `core.http_get_bytes` 里统一做了 gzip 解压。
- 得奇小说网的正文不在 HTML 里：章节页的 `#chapter-content` 是空壳，真正内容由
  `/modules/article/ajax2.php?aid=&cid=&token=&timestamp=&nonce=` 返回 JSON（站点注释说 GBK，实测是 UTF-8）。
  token 由 `/scripts/chapter.js.php?aid=&cid=` 现发，**与 cid 一一绑定**，换一章就得重新取，所以每章是两次请求。
  两个必踩的坑：① 请求必须带 `X-Requested-With: XMLHttpRequest`，缺了只回 `{"status":0}`（和 cookie 无关）；
  ② ajax 请求的 `Referer` 必须是本章页地址，写成站点根域会回「Token验证失败」。
  另外分页总数只能取 `<em id="pagestats">当前/总数</em>`，分页条只渲染当前页附近的几个数字，
  照最大值算会把 289 页的榜当成 998 页。
- 爱丽丝书屋（`reader/ali.py`）**整站只能走代理**：DNS 能解析（www 指向 128.242.240.117），
  但大陆直连 443 直接超时，所以请求层自己挑代理（设置项 → `SUDUGU_PROXY`/`ALI_PROXY` 环境变量 →
  依次试 7897/7890/10809/1080），命中后记住，失败进 20 秒冷却，避免每次搜索都白等 4 秒。
  注意 `urllib` 默认会读 `HTTP_PROXY` 环境变量，这里必须用 `ProxyHandler({})` 显式直连、用
  `ProxyHandler({"http": ..., "https": ...})` 显式代理，否则会被环境里的代理带偏。
  另外三个坑：① 分类/榜单/搜索的结果页是纯文字表格，**没有封面**，封面只在详情页
  （`.pic img` 或 `og:image`，格式是 webp，`/api/img` 要按 `RIFF....WEBP` 判 MIME）；
  ② 书籍页 id（`/novel/49271.html`）和章节里的内部书号（`/book/50585/...`）**不是同一个**，
  章节地址要原样存，不能按书籍 id 拼；③ 搜索是拆词模糊匹配（「淫乱家族」能搜出 1475 条），一页只有 10 条。
- 漫客栈（`reader/mkz.py`）是漫画站，页面本身是模板渲染，真正好用的是它的 JSON 接口：
  `comic/info/`（作品信息）、`chapter/v1/`（话目录）、`chapter/content/v1/`（每话图片列表）、
  `author/info/`（作者名，网页里抓不到，只有 `{{ item.author_title }}` 这种模板占位）。
  三个坑：① 图片地址带 `auth_key` 签名，**会过期**，所以每话的图片列表不落缓存，每次现取；
  但图片本身按 URL 的路径哈希缓存在 `data/img/`，签名轮换后仍然命中，不会重复下载。
  ② 搜索/分类接口要登录签名（`uid` + `sign`，缺了回「用户标识不能为空」或 301），
  所以只做「粘贴链接 / 数字 ID」识别，不做关键词搜索。③ 目录接口正常是正序，但个别作品会给成倒序，
  所以先看首话号是否大于末话号，是的话整体按话号重排（不动原本正序的作品，免得把番外排到正篇中间）。
- 包子漫画（`reader/gsh.py`）是 Astro 静态站，搜索和详情能直接抓 HTML，但目录和每话内容走两个第三方接口：
  `api-get-v3.mgsearcher.com/api/manga/get`（目录 + 作品信息）、`v2.apikk.top/api/v2/chapter/getinfo`
  （每话，图片是一段混淆串）。四个坑：① 两个接口**只认数字 mid**，而站上的链接和搜索结果都只有 slug，
  mid 藏在详情页的 `data-mid` 里 —— 所以书号用 slug，mid 现抓详情页、记在 `data/cache/gs_mid.json`，
  同一本书的第二话就不用再拉详情页。② 每话的图片地址是加密的：截掉 `J7r` / `nQ` 前后缀、按长度切三段重排、
  每 7 个字符的奇数段倒序、再按 64 字符表映射、base64 解出 JSON。算法固定、没有密钥，照着搬即可。
  ③ 作者名和连载状态只在详情页 HTML 里（接口没有），而且是繁体（`連載中`），读出来顺手转简体。
  ④ 图片 CDN 是 `t-nd2-1.6wm.top`，不需要 Referer；封面在另一个域（`c-nc-1.6wm.top`），走 `/api/img` 代理。
- 快看漫画（`reader/kuaikan.py`）整站是 Nuxt1 服务端渲染：详情、目录、每话的数据都嵌在页面的
  `window.__NUXT__=(function(a,b,...){...}(值,...))` 脚本里，重复的值被抽到参数表，
  参数表里还有 `Array(n)` 预分配数组（由函数体里 `g[0]=...` 语句回填）。
  所以先写了 `reader/nuxtparse.py`——一个百来行的 JS 字面量求值器（字符串/数字/数组/对象/
  标识符引用/`void 0`），不用起 JS 引擎就能把数据还原成 Python 对象。四个坑：
  ① 每话图片地址带 `sign` 签名，去掉直接 403 —— 签名在打开每话页时现发，
  所以每话的图片列表不落缓存（和漫客栈同理），图片本体按「主机+路径」缓存照样命中。
  ② 付费话（`is_free=false` 且 `can_view=false`）站点只给 3 张预览图，目录里标 🔒 提前说清楚。
  ③ 搜索接口是明文 JSON 不用登录，但 `title_and_author` 匹配很严，搜「斗罗」只出 1 本，
  属于站点行为。④ 目录一次给全（442 话的长篇也是一页），不用翻页拼装。
- 站点改版可能导致解析失效，改版后主要需要调整 `reader/core.py` 里的几个选择器。
- 端口 8791 被占用时会尝试复用已运行的实例；想换端口改 `app.py` 顶部的 `PORT`。

## 打包（EXE / APK / iOS）

详见 `packaging/README.md`：

- **Windows EXE**（已验证）：`packaging/exe/build_exe.bat`，PyInstaller 单文件（约 9MB），
  双击启动内置服务并弹出 Edge 应用窗口，数据存在 exe 旁的 `data\`。注意本机 WebView2
  运行时太旧（100.0），pywebview 方案会初始化失败，所以默认走 Edge `--app` 窗口。
- **Android APK**：`packaging/android/`，Chaquopy 内嵌 CPython 跑原版服务，
  先跑 `sync_code.bat` 同步代码，再用 Android Studio 打开构建（见其中 README）。
- **iOS ipa**：推到 GitHub 后由 Actions 云端 macOS 自动编译（`.github/workflows/build-ipa.yml`，
  Swift 壳 + beeware 内嵌 CPython 3.13，产出未签名 ipa，Sideloadly/AltStore 签名安装），
  详见 `packaging/ios/README.md`；零成本替代仍是 `start_lan.bat` 局域网模式 +
  Safari「添加到主屏幕」。
- `app.py` 支持环境变量 `SUDUGU_ROOT` / `SUDUGU_DATA` / `SUDUGU_LAN`，供各打包宿主注入。
